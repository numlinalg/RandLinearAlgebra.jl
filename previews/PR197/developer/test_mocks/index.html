Test Mocks

Many tests need a small stand-in for a Compressor or CompressorRecipe. Instead of each file defining its own, shared mock types live in test/test_helpers/mocks/.

Note

Only the compressor mocks exist so far. Other families (approximators, solvers and so on) still use types defined locally in each test file.

Where mocks live and how they load

  • Each family has one file, mock_<family>.jl, that defines one module, for example MockCompressors in mock_compressors.jl. The module exports Mock* names.
  • preamble.jl includes every mock file, so each test module has its own copy.
  • A test opts in with using .MockCompressors.

Because a mock is copied into each test module, a method defined on a mock in one file never affects another file.

Tiers

A family offers types by behavior. A test uses the lowest tier that exercises what it checks.

  • Inert: fields only, no methods. Calls fall through to the abstract fallbacks in RandLinearAlgebra, which throw ArgumentError. Use inert types to test the fallbacks and anything that depends only on the fields, such as size.
  • Working: just enough methods to test one layer. For example, a type that defines only mul! with five arguments lets the three-argument, adjoint and binary * methods be tested through it.

If one test file needs two tiers, split the file instead of defining extra methods partway through it.

Naming

  • Mock<Thing> is the inert tier.
  • Mock<Tier><Thing> is a working tier, for example MockMul5CompressorRecipe.

MockUpdateCompressorRecipe has no default for status. A test passes it explicitly, for example MockUpdateCompressorRecipe(3, 4, false), and checks it before and after the update.

Adding a mock

  1. Add the type to the family's file, or create mock_<family>.jl with a new module and include it from preamble.jl.
  2. Give every type and method a docstring that states its tier and what it does.
  3. Add a row to the table above.
  4. Render the docstrings. In docs/make.jl, include the new mock file and add its module to modules = [...]. Then add a @docs block for it in the API section below. Documenter reports any docstring in a listed module that no page includes.
  5. Replace the local copies in the test files with using .Mock<Family>. Test checks should not change.

Run the full suite afterwards, since the preamble change affects every test file.

API

Types

MockCompressors — Module
MockCompressors

Shared mock Compressor and CompressorRecipe types for the compressor tests.

The types are grouped into tiers by behavior. The inert tier holds fields only and defines no methods, so the abstract fallbacks in RandLinearAlgebra throw ArgumentError. Working tiers define just enough interface to test one layer.

Note

This file is included from preamble.jl, which is included within individual modules fore each test file, so each test module gets its own copy of MockCompressors. Methods defined on a mock in one test file therefore never leak into another test file.

Main.MockCompressors.MockCompressor — Type
MockCompressor <: Compressor

Inert Compressor with no fields and no methods. Calling complete_compressor on it reaches the abstract fallback and throws an ArgumentError.

source
Main.MockCompressors.MockCompressorRecipe — Type
MockCompressorRecipe <: CompressorRecipe

Inert CompressorRecipe that holds only its dimensions and defines no methods. Use it to test functionality that depends only on n_rows and n_cols (size, adjoint, dimension checks), and to check that update_compressor! and mul! fallbacks throw an ArgumentError.

Fields

  • n_rows::Int64, the number of rows of the compression matrix.
  • n_cols::Int64, the number of columns of the compression matrix.
source
Main.MockCompressors.MockMul5CompressorRecipe — Type
MockMul5CompressorRecipe <: CompressorRecipe

Working-tier CompressorRecipe that defines only the two five-argument mul! methods. The library's three-argument, adjoint and binary * methods all reduce to these, so they can be tested through this type. A left multiplication fills the output with -1 and a right multiplication fills it with -2.

Fields

  • n_rows::Int64, the number of rows of the compression matrix.
  • n_cols::Int64, the number of columns of the compression matrix.
source
Main.MockCompressors.MockMul3CompressorRecipe — Type
MockMul3CompressorRecipe <: CompressorRecipe

Working-tier CompressorRecipe that defines only the two three-argument mul! methods, which are more specific than the library's three-argument fallbacks. The five-argument methods are never reached. A left multiplication fills the output with 1 and a right multiplication fills it with 2.

Fields

  • n_rows::Int64, the number of rows of the compression matrix.
  • n_cols::Int64, the number of columns of the compression matrix.
source
Main.MockCompressors.MockUpdateCompressorRecipe — Type
MockUpdateCompressorRecipe <: CompressorRecipe

Working-tier CompressorRecipe that defines only the one-argument update_compressor!. The library's two-, three- and four-argument methods all reduce to it, so they can be tested through this type. The status field records whether an update has run.

Fields

  • n_rows::Int64, the number of rows of the compression matrix.
  • n_cols::Int64, the number of columns of the compression matrix.
  • status::Bool, false until update_compressor! runs.
